01 // HIGH-THROUGHPUT APIS & STORAGE Slashing Chat History Latency by 83% with Snowflake IDs & Cursor Pagination
PostgreSQL · Snowflake ID · Rate-Limiting

The Bottleneck: Offset-based pagination and non-monotonic identifiers caused expensive index scans as conversation histories grew across enterprise tenants, while bursty client retries degraded tail latency.

  • Time-Sortable 64-bit Snowflake IDs: Replaced random identifiers with k-sortable 64-bit Snowflake IDs encoding timestamp, worker ID, and sequence number, turning historical window queries into O(log N) B-Tree range seeks.
  • Distributed Rate-Limiting: Paired the endpoint with a custom distributed rate-limiter across microservices, cutting abusive traffic and improving compute utilization by 35%.
[Client] ──► [Distributed Rate-Limiter (Redis)] ──► [Chat Service (gRPC)]
                                                          │
   SELECT * FROM messages                                 ▼
   WHERE channel_id = $1 AND id < $cursor_snowflake_id  [PostgreSQL Composite Index]
   ORDER BY id DESC LIMIT 50;                           (channel_id, id DESC) -> -83% Latency
02 // CONCURRENCY & DATABASE HARDENING Scaling to 5,000+ Concurrent Sockets & Resolving ~200 TPS DB Saturation
Redis · PostgreSQL · MongoDB · k6

The Bottleneck: Profiling AI & search workloads under load revealed two critical ceilings: PostgreSQL CPU saturation capping throughput at ~200 TPS, and MongoDB/Redis disk I/O contention combined with write amplification on 2MB+ search payloads.

  • Cache & Storage Isolation: Migrated Redis state to isolated GCP MemoryStore to eliminate shared disk I/O contention and restructured 2MB+ MongoDB payload writes to mitigate write amplification.
  • Connection Pool Tuning & k6 Verification: Explicitly tuned PostgreSQL connection pools to prevent connection exhaustion under bursty AI worker traffic and authored automated k6 load-testing suites validating stability across 5,000+ concurrent socket connections.
03 // AI INFRASTRUCTURE & COST GUARDRAILS Event-Driven LLM Evaluation & Pre-LLM Voice/PII Guardrails (Cleartrip Launch)
Kafka · Presidio · Anthropic Haiku

The Problem: At enterprise launch scale (including Cleartrip), cron-based session evaluation created a backlog of 4,900+ blocked sessions, while unvalidated voice notes and raw user PII risked both compliance exposure and wasted LLM token spend.

  • Pre-LLM Cost & Safety Gating: Tuned Microsoft Presidio for person-name PII redaction paired with Claude Haiku language detection, and rejected unsupported-language voice notes across Agent, CMS, and Chat services before invoking downstream LLMs.
  • Event-Driven Evaluation & Async Itinerary Engine: Replaced the cron evaluator with event-driven worker pipelines (clearing 4,900+ queued sessions) and built a Kafka async recommendation pipeline that cut itinerary generation time by 50%.
